# EAS setup and release guide

NexKey is prepared for EAS Build and EAS Update, but it is not linked to an Expo account yet. The project ID and update URL must be generated by Expo; do not insert a made-up ID.

## One-time account linking (required)

1. Create or sign in to an Expo account at https://expo.dev.
2. Open the NexKey repository in a terminal environment (for example, GitHub Codespaces) and run:
   `npx eas-cli@latest login`
3. From the repository root, run:
   `npx eas-cli@latest init`
   Choose or create the Expo project for NexKey. This generates the real EAS project ID.
4. Then run:
   `npx eas-cli@latest update:configure`
   Commit the generated `extra.eas.projectId` and `updates.url` changes to `app.json`.
5. Add an Expo access token to GitHub:
   - Create a token in the Expo account settings.
   - In GitHub, open Settings → Secrets and variables → Actions → New repository secret.
   - Name it exactly `EXPO_TOKEN` and paste the token into GitHub's secret field. Never paste the token into chat or commit it to the repository.

## Build an APK from GitHub

After linking the EAS project and adding `EXPO_TOKEN`:
1. Open the repository's Actions tab.
2. Select **EAS Build** → **Run workflow**.
3. Choose `android` and `preview` (or `production`) and run it.
4. Open the EAS build link in the workflow logs to download the generated APK when the build completes.

Both Android profiles are configured to produce APK files. iOS builds use the corresponding EAS iOS build process and require Apple's signing setup.

## Publish an in-app update

1. Open Actions → **Publish EAS Update** → **Run workflow**.
2. Enter a short release note and run it.
3. Compatible installed builds on the `production` channel can receive the update through the NexKey Settings updater / Expo Updates.

## Important limits

- OTA updates are only for compatible JavaScript, UI, and bundled asset changes.
- Changes to Kotlin/Swift keyboard engines, native permissions, native dependencies, or extension configuration require a new native build.
- Android installation/update requires the user's approval through the package installer or a trusted store. iOS native updates go through the App Store.
- The GitHub workflows do not create an Expo account or project on your behalf. The one-time linking step above is mandatory.
